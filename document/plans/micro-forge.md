# micro-forge 规划

## 这个仓库是什么

micro-forge 是用 C++23 写的 ARM Cortex-M3（STM32F103）模拟器，支持完整 Thumb-16/32 指令集与 ARMv7-M 异常模型，模拟 NVIC、SysTick、RCC、GPIO、USART、TIM 等外设。不需要买开发板，就能运行和测试真实的 STM32F103 固件（含 STM32F1 HAL）。它在组织里有两重身份，一是学习地图单片机线的模拟层，二是 [ST-Forge](/projects/st-forge) 实验的模拟验证配套。

在[学习地图](/roadmap/02-mcu/)的验证顺序里，纯逻辑先在 Host 上测试，受支持的功能语义与故障在 micro-forge 里验证，电气、时序、功耗和板级兼容留给真板实验。每个实验要写清楚自己实际通过了哪一层。

仓库正在整体重写。重写的定位是教学外设台，也就是把外设模拟做成教学上能直接上手试玩的界面。计划中的指令面板（查看与控制指令执行的界面）和外设试玩页签（在前端页面上手操作外设）都属于这个方向。

## 现状

本节的数字与事实来自仓库 README、CHANGELOG、提交历史与组织快照，查询日期随文标注。

2026-10-02 的组织快照记录 6 星、1 fork、0 条开放 issue，主语言 C++，MIT 许可，仓库创建于 2026-05-15，最后提交 2026-08-02。

README 自述，测试有 19 个测试文件共 353 个 GoogleTest 用例，Qt6 GUI 仪表盘为可选构建。

CLI 支持 run、dump-mem 与 snapshot-json 状态导出，端到端跑通过真实 Keil/MDK-ARM STM32F103 HAL 固件。测试数与覆盖率是 README 自报，未独立复核。

版本方面，v0.2.0 发布于 2026-07-07，CHANGELOG 记有覆盖率流水线。main 分支最后一次合并是 PR #14，内容为 JIT 统一 IR 与 GUI 提速系列，时间是 2026-08-02。

仓库当前处于整体重写阶段，这是组织 2026-10 的路线记录。重写推进到哪一步、在哪个分支上进行，公开渠道查不到，待核实。

## 下一代方向

方向是重写收官后按消费者补能力。消费者指真实使用这个模拟器的上游仓库，当前登记的候选是 ST-Forge 需要的模拟验证，以及组织内的 bootflint（公开后补入口）需要的 FLASH 模型。

按消费者补，是因为一项模拟能力写完只是开始，有没有人真用、用的时候缺什么，只有真实消费者的反馈能回答。没有消费者的外设模型得不到使用反馈，还会变成持续的维护负担。

重写收官之前，新能力不进这个仓库。指令面板和外设试玩页签本来就要放进 micro-forge，但仓库正在重写，新代码现在放进去，重写铺开时就得跟着搬第二次。这两件等收官后再放进仓库，教学外设台的界面形态到那时一并确定。

下面的事还没定下来，登记为待定项。

- ST-Forge 的模拟验证与 bootflint 的 FLASH 模型哪个先做，取决于哪个需求先确认，待定。
- 教学外设台的具体形态，包括指令面板与外设试玩页签怎么分工，待定。

## 近期要做的事

- 补上重写的公开进度。现在从 README 和 issue 都看不出重写进行到哪、在哪个分支上进行。做完的标志是从 README 或 issue 就能查到重写的进度与分支。
- 推进重写收官。收官是指令面板、外设试玩页签和其他新能力进仓库的前提。做完的标志是重写后的架构合入 main，README 反映重写后的结构。
- 为第一个确认需求的消费者补一项模型能力，并配回归测试（保证已有行为不被新改动破坏的测试）。消费者自己的开工不等整个重写收官，先满足它需要的那一项能力。做完的标志是该能力合入 main、带回归测试，并有消费者仓库真实在用。

## 边界与不做的事

- 重写收官之前，新能力不进这个仓库。
- 模拟通过不写成硬件通过。模拟只覆盖已经实现并回归过的 CPU 与外设行为，不替代电气、时序、功耗与真板实验。
- 能力跟着确认的需求走，不为想象中的用法预先开发外设模型。教学外设台也一样，启动条件是一个明确的外设教学需求。
- 教学外设台不开新仓库，相关能力都放进 micro-forge。
- 本页不承诺日历排期，"近期"指动手的先后，不指日期。
