# C-Journey 规划

## 这个仓库是什么

C-Journey 是组织教学线的 C 语言进阶教学仓库，定位是用 C 游历计算机世界（CHANGELOG 2026-07-03 条）。全书分八个阶段，从开发环境一路走到嵌入式 C 与综合项目，每个阶段配套知识点文档、示例、练习和配套项目（如 clib-utilities、tiny-c-stdlib、os-from-scratch）。仓库本身是 VitePress 文档站，部署在 GitHub Pages，持续集成有六项检查，覆盖编译、内存安全、静态分析、覆盖率、格式与文档校验（来源：仓库 README 与 CONTRIBUTING）。各阶段的当前范围以仓库 README 为准，路线概览见[项目页](/projects/c-journey)。

## 下一代方向

主推方向是把工作重心从站点维护升级为先收尾存量事项，再做定向重写。先处理悬置的分支与过时的记录，再把重写力气集中到阶段 0 与阶段 3，其余阶段只做纠错维护，这两个阶段收尾后再评估是否继续全量重写。

- 节奏对不上。重写方案定稿两个月，完成量是阶段 0 两章加阶段 3 一批，按这个节奏推进全书 83 章要数年，而组织的开发精力要分给多个仓库，全量目标与现实节奏对不上。
- 读者价值排序。学习地图把 C-Journey 排在基础链的 C 一站，前站是 EmbedBox，后站是 Tutorial_AwesomeModernCPP（[学习地图](/roadmap/01-fundamentals/)）。从这条路过来的读者最依赖阶段 0 到 3 的质量，也就是环境、C 基底、指针内存与数据结构。阶段 4 与 5 已写完上线且检查全绿，读者被卡住的可能性低。阶段 3 已开工未完结，先收它收益最高。
- 质量约束保留。一次只写一章、经维护者确认后才合并这两条约束不变。阶段 3 在 09-01 先于既定顺序重写，全量顺序目标已经守不住，把目标改成分段，同时保住真正防质量滑坡的两条约束。

嵌入式方向的接线可以提前做。ST-Forge 的课程路线已定稿（P0 到 P7，芯片锁 STM32F103C8T6，C 是唯一主线），它的第一批读者需要一个 C 入口，bareline 也在等真实的 ST 工程消费它来完成课程交接。C-Journey 与这条链的链接设计和无板可跑示例不必等全书重写完成，阶段 6 入门章的正文本身仍等方向确定，本轮只出目录稿。

## 近期要做的事

- 收尾存量记录。用一个 PR 处理 rewrite/ch01 分支（差异核对后并入或归档），把重写状态记录更新到 10 月实况，README 章节表改为阶段 0 共 19 章、阶段 3 共 16 章、合计 90。这项做完的标准是分支处置完毕、章节表与磁盘一致、六项检查与 check_links.py 全绿。
- 完结阶段 3。按定下来的结构把阶段 3 剩余章节写完或裁完，jyp_vector 与 examples 反向链接进正文。做完的标准是阶段 3 标记完结，每章通过六项检查，目录结构与登记一致。
- 阶段 6 入门章目录稿。设计入门章的目录与链接，每章末尾指向 bareline、ST-Forge、imx-forge 的对应入口，附一个改造成 QEMU 可运行的示例方案。做完的标准是目录稿经维护者评审通过，示例在无板环境跑通一次并留下运行记录。
- 站点 base 路径参数化。部署路径目前写死为 /C-Journey/，配合中心站的本地联合构建需要参数化。做完的标准是同一份配置既能部署到当前线上地址，也能产出可挂进本地门户的构建结果。

## 边界与不做的事

- 不做跨 forge 的合并或模板抽取。imx-forge、rk-forge、h618-forge 是三个独立项目，面向不同芯片，各自演进。
- 嵌入式深入实践不在本仓做。阶段 6 只做入门引导，板级深入走 ST-Forge 与 imx-forge。
- 站点工程不再做大改动。站内搜索与判题练习保持暂缓，重写推进本身不自动解锁这两项。
- 不做英文版。先把中文版做扎实，英文版暂不排期。
- 不恢复已被重写路线取代的逐章精修方案。
- 阶段 3 的结构定下来之前，不新建进阶篇目录。
- 阶段 7 与现有进阶内容的重叠，等结构定案再处理，不预先写结构。
- 本页只写产物与完成标准，不写日期承诺，整体时间视图见[路线与进行中](/todo/)。
